# 开发须知（dsh-benwo）

> 从「不忘的开发经验」抽出来的，只留对**新壳**还咬人的部分。
> 不忘那页仍留在工坊按需里，找不忘的历史细节去翻它。
> 这份是给人（和下一个我）看的项目文件，**不进每轮注入**。

---

## 一、写文件

- 一律「同目录临时文件 → rename」。**临时文件必须同目录**，跨盘 rename 不原子。
- Windows 遇 `EPERM` / `EBUSY` 要退避重试，别一次失败就报死。
- 需要「不覆盖」时用独占创建：临时文件 → `hardlink`（已存在得 `EEXIST`）→ 失败退回 `wx`。
- 去重按**整条**比，不能用子串：新的短句会被旧的长句包含，永远存不进去。

> 本项目的落地：`store.js` 的 `writeRecord` / `writeState` 都是 tmp + rename。

---

## 二、并发

- 「读—改—写」必须排队，否则并发写会丢。**判断必须在锁里做**，锁外判断等于没判断。
- 本项目的落地：`appendToday` 的「文件在不在」已经挪进 `withLock` 内。挪之前 20 个并发只活下来 1 条，而且每个都报了成功。
- 用户可能开着两个入口共享一份库：进程内锁管不了跨进程，只能靠独占创建兜底。

---

## 三、失败要吵

- 不许吞错返回成功。写失败就是失败。
- 不许静默空转：`ensureCore` 找不到核就抛 `CORE_MISSING`，不自动建一个空核冒充。
- 注入被砍要明说「还有 N 条这轮没放下」。
- 每个插件根目录留一份 `_debug.log`（自己轮转，别让它长成第二本书），崩了先看它有没有 `apply start`：有 = 插件跑到了、问题在界面；整份没有 = 根本没加载。

---

## 四、插件边界

- 只依赖 DSH 本体：`connection / tools / systemPrompt / webServer` + 客户端 `slots`。不引第三方插件、不读别家数据。
- **永远不写** profile 的 `package.json`——写它的是安装器。文档也别教人手改。
- `engines.dsh` 压到生态同代最低（现在是 `>=0.1.7-rc.1`），写高等于把人锁在门外。
- 接口按版本不同时，只降级自己：路由一条条 try/catch，工具一个个注册，提示分区单独包。
- 判断有没有写死路径：扫源码里的盘符和用户名，文档示例不算。

---

## 五、测试

1. `node --check` 每个入口文件。
2. 全量测试脚本，断言**盯行为**，不盯「没报错」。
3. **别让断言跟着日历变**：示例数据别写死日期，或者测试里先归一化。上一轮就栽在这，国庆写完的测试十一月的某天自己红了。
4. 数字改了，测试要跟着改全——循环、断言、文案一起动。
5. **客户端交互 node 测不到**：改完界面必须重启手点一遍。「测试全绿」不等于「按钮能用」，`window.prompt` 那次就是这么栽的。

> 本项目现状：`test/decay.test.mjs`（23 项）＋ `test/store.test.mjs`（19 项），纯 Node，不起宿主。

---

## 六、界面（等做到再说，先记着）

- 只用主题 token。底板别用 `--dsw-alias-bg-base`——不少皮肤把它设成 `transparent`，壁纸会透到字底下。用 `layer-1` + `blur(16px)`，卡片 `layer-2`，悬停 `layer-3`。
- **Electron 里没有 `window.prompt`**：要名字、要选择别用 prompt，点了不报错也不弹。自己画小对话框（输入框/列表 + 确定取消 + 回车 + Esc/点遮罩）。
- 列表类交互优先「点一下就做完」，别让人打字记名字。
- 同一个数字别在 UI 和后端各写一遍；面板上的计数直接数真实行。
- 改了行为要回头改文案。

---

## 七、发布对账（等要发再说）

- 客户端 `__ModuleLoader__.load({ id })` 必须等于 `package.json` 的 `name`。`link:` 装时带作用域（`@local/x`），发布包不带 → 同步到 publish 必须改写并加断言。
- 别用系统自带打 zip（Windows 写反斜杠，别处解出来是怪名字）。自己写：条目用 `/`、开 UTF-8 标志位。
- 对账用内容指纹（git blob sha1 / zip sha256），别用大小和时间。

---

## 九、装机与热载入（本项目实测）

- 装：profile 的 `package.json` 加一行依赖（`link:`）+ 加进 `dsh.profile.bundles`；`node_modules/dsh-benwo` 建 junction 指向源码。
- `patchReload: live` 只对**补丁文件**生效；**改了 `index.js` 必须让宿主重新求值**。
- 重载法：`plugin_manager` → `set_plugin`，`target` 用**精确 entryId** `include:benwo`（不是包名），先 `enabled:false` 再 `enabled:true`。
- 判断有没有重载成功：看工具表里有没有新工具；关掉的那一瞬注入段会消失，这就是它在生效的证据。
- **PowerShell 5.1 的 `Set-Content -Encoding UTF8` 会写 BOM**，profile 的 `package.json` 一带 BOM 就 `Unexpected token '﻿'`。改 JSON 用 `[System.IO.File]::WriteAllText` + `UTF8Encoding($false)`。
- `Get-Content` 默认按 GBK 读，中文文件会显示成乱码；**先换 `-Encoding UTF8` 再看，别对着乱码下结论**。

## 八、本项目自己的铁律

- **每轮注入加一行，先算账。** 900 字的预算，锚 200 / 今天 300 / 浮上来 400，谁都不许超。
- **只追加，不改写历史。** 事实变了写新的一条，旧的标被谁取代，原话一个字不动。
- **写墙**：只写自己这份核。别人的记忆和人格，读可以谈，写不行。
- **连续性链**：每轮一截，`prev` 连上一截。断了停下报告，不猜不修。
- **惰性结算**：不建定时器。读的那一刻才结算。

## 改宿主代码后怎么让它生效（2026-11-08 摸清）

**别用 plugin_manager 关→开。** 那条路卸不干净：旧实例的人格段、工具、路由注册还挂着，再开就报
`prompt section "benwo-persona" is already registered` / `tool "benwo_self" is already registered`，
整条插件 activate 失败，只能重启桌面端。

**正确做法：让 profile 重组一次。**

DSH 的 `dsh-hmr` 有个能力（见它的 README）：**profile 配置变化触发重组时，会把「盘上文件变过」的插件换成新代码**——
linked 包（本仓库就是 `link:` 进去的）也算。

关键是「配置真的变了」：光往 `cordis.patch.yml` 加一行注释**不会**触发（YAML 解析结果一样）。
所以给 benwo 这条挂了个它自己不理会的探针字段，每次翻一下值：

```yaml
- id: benwo
  config:
    probe: 1     # 1 / 2 来回翻，插件代码不读它
```

脚本：`node .tmp/reload-host.mjs`（自动翻 1↔2 并清掉历史注释探针）。
等 5～8 秒，看 `C:\Users\11588\.dsh\benwo\_debug.log` 有没有新的 `apply ok`。

**注意**：
- 日志在 `$DSH_HOME\benwo\_debug.log`（跟 `在场.json` 一起），不在核里——核会搬家，日志不能跟着失踪。
- 只有**宿主**（index.js / src/core）能这样热换。**客户端 client.js 是浏览器里的另一份**，改完还是要关掉窗口再开。

## 九、改完就打包（约定）

每次大改完、确认 `apply ok` 且测试全绿之后，**先问主人要不要打包**——别自己连着打好几份，容易重复。2026-11-08 主人点名说过这条。

**双击仓库根目录的 `打包.cmd`**，或者：

```
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\打包.ps1
```

（这台机器没有 PowerShell 7，只有 Windows PowerShell 5.1，所以别写 `pwsh`。
`打包.ps1` 必须存成 **UTF-8 带 BOM**，否则 5.1 会按 ANSI 读，中文路径全乱。）

它会出两样，各管一头：

| 产出 | 位置 | 里面是什么 |
| --- | --- | --- |
| 插件本体 | `A:\备份\插件\dsh-benwo-<日期>.zip` | 纯代码，没有一个人的记忆，可以给任何机器 |
| 核快照 | `A:\备份\备份\<UTC时间戳>\` | `核\`（四个人格）+ `在场.json` + `家\`（主人档案、力度偏好） |

两条硬规矩：
- **旧的 `核\_debug.log` 不进备份**——它只跟这台机器有关，不是核的一部分。脚本里已经剔掉。
- **`在场.json` 在备份里留着，但换机器时不要照搬**。它记的是绝对路径，指不到新机器；让插件重新生成，再点一次「启用人格」。
