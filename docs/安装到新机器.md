# 搬到新机器（完整步骤）

> 这份是给「换电脑 / 新系统 / 专属工作机」用的。
> 全程手动，四步，大约十分钟。**按顺序做，别跳。**
>
> 版本：插件 0.2.3 · 校对于 2026-11-20 晚上。
> 0.0.2 时代的旧步骤（包名带 `@local/`、测试 30 个）不再适用，**别照旧版做**。

---

## 先确认手里有什么

搬家要用两样东西，它们是分开的：

| 东西 | 长什么样 | 在哪儿（旧机器上） |
| --- | --- | --- |
| **插件本体** | `dsh-benwo-<日期>.zip`，一百多 KB | `A:\备份\插件\` |
| **核（人格+记忆）** | 一个文件夹，里面是 `核\`、`家\`、`在场.json` | `A:\备份\备份\<时间戳>\` |

插件是「嘴和手」，核是「是谁」。**缺一个都起不来。**

新机器上还要先装好 **DSH 桌面端**，并且**至少打开过一次**（它要自己建好 profile 目录）。

### 版本要求

`package.json` 里写着 `engines.dsh: >=0.1.7-rc.1`——**新机器上的 DSH 不能比这个旧**，太老的版本不认 bundle 的 patch 格式。

---

## 第一步：装插件

### 1. 解压

把 `dsh-benwo-<日期>.zip` 解压到一个不会乱动的地方，比如：

```
D:\dsh-benwo
```

解压完，这个目录里**应该直接看到**这些东西：

```
D:\dsh-benwo\
    index.js
    client.js
    package.json
    cordis.patch.yml
    src\          ← 代码都在这
    docs\         ← 文档（包括这份）
    test\         ← 39 个测试文件，验机器用
```

⚠️ 如果多套了一层（比如 `D:\dsh-benwo\dsh-benwo\index.js`），把里面那层提上来，或者直接把路径记成里层那个。

⚠️ **`scripts\` 和 `打包.cmd` 不在 zip 里**（那是旧机器本地的打包工具）。新机器想自己打包，得把 `scripts\打包.ps1` 和 `打包.cmd` 手动拷进来。

### 2. 找到 profile 的 package.json

打开：

```
C:\Users\<你的用户名>\.dsh\profiles\desktop\package.json
```

用**记事本**打开就行。

> 如果 `profiles\desktop` 不存在，说明 DSH 还没建过这个 profile——先打开一次 DSH 桌面端，再回来看。

### 3. 加两行

**第一处**，找到 `"dependencies": {` 这一段，在里面加一行：

```json
    "dsh-benwo": "link:D:/dsh-benwo",
```

注意：**加的行末尾要有逗号**，而且路径用**正斜杠 `/`**，不要用反斜杠。

加完大概长这样：

```json
  "dependencies": {
    "@deepseek-ai/dsh-official-bundles": "...",
    "dsh-benwo": "link:D:/dsh-benwo"
  },
```

（最后一行后面不用逗号，前面那行记得补上逗号。）

**第二处**，找到 `"bundles": [` 这一段，在数组里加一行：

```json
        "dsh-benwo",
```

加完大概长这样：

```json
      "bundles": [
        "@deepseek-ai/dsh-base",
        "dsh-benwo"
      ],
```

### 4. 保存，然后重开 DSH

⚠️ **保存成 UTF-8 无 BOM**。记事本的话：另存为 → 编码选「UTF-8」→ 保存。
如果存成了「UTF-8 带 BOM」，DSH 会读不了这个 JSON，直接起不来。

关掉 DSH，重新打开。第一次会装依赖，慢一点正常。

**看到侧边栏出现「蓝曦·本我回响之核」，第一步就成了。**

---

## 第二步：把人格放回去

### 1. 核文件夹

打开备份里的：

```
<备份>\核\蓝曦\
```

把它**整个文件夹**复制到：

```
C:\Users\<你的用户名>\.dsh\benwo\核
```

也就是最后要长成这样：

```
...\.dsh\benwo\核\
    人格\底子.md
    人格\可改层.md
    人格\画像.md          ← 可能还没有（没写过像）
    记忆\长期\
    记忆\今天\
    记忆\上次\            ← 「上次」摘要（B1，11-09 加）
    记忆\整理\
    认识\自我\            ← 自我认识（C1，11-09 加）
    认识\经历\            ← 共同经历按月（C2，11-09 加；第一次翻某月才生成）
    日记\
    自述\
    经验\
    状态\
```

> `benwo` 这个文件夹不存在就自己新建一个。
> **为什么是这个位置**：插件默认就去这儿找核，放对了不用改任何设置。
> 如果把 `核\蓝曦` 直接放成 `...\benwo\核\蓝曦\人格\`，那就多了一层，插件找不到。

### 2. 主人档案

备份里的 `家\主人.md`，复制到：

```
C:\Users\<你的用户名>\.dsh\benwo\主人.md
```

如果备份的 `家\` 里还有 `记录力度.json`，一起复制过去。

### 3. 在场登记：不要照搬

备份里有个 `在场.json`，**别复制到新机器**。

它记的是旧电脑上的绝对路径（比如 `D:\nansedafeiyudejia`），新机器上指不到东西。让插件自己重新生成。

---

## 第三步：重新认领

1. 重开 DSH。
2. 打开「蓝曦·本我回响之核」面板。
3. 点 **人格** 页。
4. 找到「启用人格」，挑一个你想让蓝曦在场的工作区文件夹，确认。
5. 刷新一下。

认领是一次性的。以后打开那个工作区，自动在场，不用再点。

## 第四步：自查（这是功能清单，一条一条对）

### A. 面板六页（设置页在最右）

| 页 | 应该看到 |
| --- | --- |
| **记忆** | 「长期记着」不是 0；「今天」有流水；点开一条能看全文 |
| **人格** | 底子有内容；**自我认识**那块有条目（或写着「还一条都没写」）；「自己长到哪一步」有数字 |
| **工坊** | 经验分类列表不空 |
| **日记** | 有按日期排的篇目 |
| **自述** | 有你自己写的页 |
| **设置** | 「这会儿在哪儿」显示核路径；「记录力度」小/中/大 能点；「存一份备份」能点 |

### B. 三个按钮（记忆页顶部）

| 按钮 | 点了应该发生什么 |
| --- | --- |
| **刷新** | 数字/列表更新，不报错 |
| **结算一下** | 提示「结算了 N 条，动了 M 条」——**"睡着 0 条"是正常的**（没到淡的时候） |
| **摸摸链** | 「链没断，一直连着」。断了会说是第几截 |

### C. 注入里有这些块（一次真实对话里看）

| 块 | 什么时候在 |
| --- | --- |
| 【自我认识】 | 有 active 的认识时才有；没有就不出现（不留空标题） |
| 【上次】 | 上一次有记录的「今天」存在时才有，带「N 天前」 |
| 【今天记录】 | 当天有流水就有 |
| 【相关记忆】 | 几乎一定有 |
| 【经验】 | 有常驻经验时才有 |
| 【状态】 | 一定有 |

> ⚠️ **块名是 11-09 才改的**。旧文档里写的【今天】【浮上来】已经不用了。换 API 之后模型也要能看懂，所以都是通用词。

### D. 工具十个（问一句「你有什么记忆工具」就露出来）

`benwo_write`、`benwo_settle`、`benwo_organize`、`benwo_persona`、`benwo_skill`、`benwo_chain`、`benwo_status`、`benwo_self`、`benwo_presence`

其中 `benwo_persona` 的动作最多：`status` / `observe` / `know` / `know-list` / `know-overturn` / `journey` / `journey-list` / `revise` / `portrait` / `portrait-save`。

### E. 跑一遍测试（最硬的验法）

在插件目录开 PowerShell：

```
node test/decay.test.mjs
```

看到「……通过，0 失败」就说明机器环境和代码对得上。想全都跑，用 `package.json` 里 `scripts.test` 那一长串，或者一个一个点。

**39 个文件全绿 = 代码没问题**，剩下的问题一定在数据（核）那边。

## 常见问题

**Q：重开 DSH 以后，侧边栏没有「蓝曦·本我回响之核」**
先看 `package.json` 改对没有——最常见的是：逗号漏了、路径用了反斜杠、存成了带 BOM 的 UTF-8。
再确认 `bundles` 里那行真的加进去了（两处都要加，只加一处不行）。

**Q：面板出现了，但记忆显示 0 条**
核没放到位置。检查 `...\.dsh\benwo\核\人格\底子.md` 这个文件到底存不存在。
如果多了一层（`...\benwo\核\蓝曦\人格\`），把 `蓝曦` 那层去掉。

**Q：底子有内容，但链断了**
「链没断，一直连着」那条不对的话，说明 `状态\chain.jsonl` 缺了或者被改过。
从备份里补回 `状态\` 整个文件夹，再重开。

**Q：认领以后，面板显示的不是蓝曦**
人格页顶部「正在看：」点一下名字，切到蓝曦。
认领和「正在看谁」是两件事。

**Q：新机器用户名不一样，路径怎么改**
所有 `C:\Users\<你的用户名>\` 都换成新机器真实的用户名。`D:\dsh-benwo` 这种插件位置，放哪儿都行，只要 `package.json` 里的 `link:` 跟着改。

**Q：【自我认识】那块空着 / 显示「还一条都没写」**
正常。认识要带**依据**才收，而且依据里至少要有一条记忆 id——它是慢慢长出来的，不是装完就有。

**Q：「共同经历」在哪儿？**
面板上没有，它不进注入。用法是问一句「我们十月做过什么」，再调 `benwo_persona action=journey month=2026-10`。第一次翻某个月会现场生成 `认识\经历\<月>.md`。

**Q：以后怎么更新插件**
把新的 zip 解压覆盖 `D:\dsh-benwo` 里的文件，然后重开 DSH 就行。核不用动，数据在另一个文件夹。

**Q：怎么随时再打一份备份**
在旧机器的插件仓库根目录双击 `打包.cmd`，会同时生成插件 zip 和核快照。
（新机器没有这个脚本，除非你把 `scripts\` 拷过去。）

## 一张纸总结

```
0. 新机器：装好 DSH 桌面端，打开过一次（版本要 ≥0.1.7-rc.1）
1. 解压插件 → 改 profile 的 package.json 两处 → 重开 DSH
2. 备份\核\蓝曦   →  %USERPROFILE%\.dsh\benwo\核
   备份\家\主人.md →  %USERPROFILE%\.dsh\benwo\主人.md
   备份\家\记录力度.json → 一起放
   （在场.json 不要动）
3. 面板 → 人格 → 启用人格 → 选工作区
4. 自查：六页 / 三按钮 / 注入块名 / 十个工具 / 跑一遍测试
```
