## 零、读这份之前必须知道的四条硬约束

1. **注入分两段，位置决定钱。**
   - `systemPrompt.section`（人格段）＝**字节冻结**，只许放不随时间变的东西。
   - `systemPrompt.context`（记忆段尾部）＝会变的都放这儿。
   - 违反这条 = 整个请求前缀掉 KV cache。实测教训来自 `@jipika/dsh-memory`。
   - 回归锁：`test/cache-stable.test.mjs`（含源码守卫）。

2. **注入里的词必须是通用词。**
   不许出现「浮上」「工坊」「记录档」这种只有本机和蓝曦懂的暗语——换 API 之后模型看不懂。
   现行命名见 `src/core/inject.js` 顶部常量：`【经验】/【今天记录】/【相关记忆】/【关于用户】/【状态】/【提示】`。
   **改名字要同步改测试**，`floating.test.mjs`、`inject.test.mjs` 都是按字面断言的。

3. **重要度写入时定一次，之后不许改**（`核 v1.0 七个坑` + `开发经验 §三`）。
   它代表「当时的判断」，改它就等于伪造历史。

4. **并发判断必须在锁里**（`开发经验 §四`，这个坑踩过两次）。
   判「文件在不在」放锁外 → 并发全判成不在 → 一起覆盖写 → 只活一条。

## 一、期 B：让记忆装得下、说得准

### B1 · 昨天进注入（治「日抛型记忆」）

**病**：`refresh()` 只读 `dayOf(now)`。昨天的 `今天/*.md` 在盘上，但没有任何一轮会看。
跨天连续性只靠 6 条相关记忆。

**做法**（选一种，建议 a）：

**a) 收工摘要（推荐）**
- 收工时（或次日首次 pre-step 补课）把当天 `今天/*.jsonl` 压成 2～3 行文本。
- 存成 `记忆/昨天/<YYYY-MM-DD>.md`，格式极简：
  ```
  # 2026-11-09
  聊了核的 bug 修复；装了什么、改了什么、结论是什么。
  ```
- 注入时读「最近一天的昨天文件」，放在【相关记忆】之前，块名 **【昨天】**，预算 ≤ 120 字。
- **不要用模型生成**（`dsh-memory-tiers` 的原则：「没有模型就不产生摘要，不许假装整理过」）。
  机械抽取：取当天 jsonl 的 `名` 字段，按时间顺序串成一句；没有 `名` 的（legacy）取正文前 30 字。

**b) 直接把昨天文件塞进注入**——否决。一天几十条，预算直接爆。

**改哪**：`src/core/store.js`（新增 `readYesterdaySummary` / `writeYesterdaySummary`）、`index.js refresh()`、`src/core/inject.js`（新块 + 预算）。

**怎么验**：
1. 造两份假数据（前天的今天文件 + 昨天的今天文件），`readYesterdaySummary` 返回昨天那份。
2. 注入里出现 `【昨天】` 且字数 ≤ 120。
3. 昨天没有任何记录时，**不出现空块**（不许留一个光秃秃的标题）。

**风险**：块名要通用，不能叫「昨天大概」这种口语；预算要从现有 650 里挤，得同时下调今天的 250 或相关的 400，否则总预算爆。

### B2 · `有效到`（治「重要度 5 永久占位」）

**病**：`injectable()` 是 `s≥12` 或 `(重要度5 且 s≥6)`。重要度 5 半衰期 70 天，从 40 掉到 6 要 ~190 天。
`rankFloating` 排序 `强度 + 5×(重要度−3)`，重要度 5 直接 +10 分 → 长期霸占名额。

**做法**：
- 记忆 frontmatter 加字段 `有效到: YYYY-MM-DD`（空 = 长期有效）。
- `injectable()` 加一条：`有效到` 早于今天 → 不进自动浮上（但**不删、可召回、面板可见**）。
- `benwo_write` 加参数 `validUntil`。
- 到期不自动清空，只是「不再主动晃」——跟「沉下去」同一个哲学。

**改哪**：`src/core/decay.js`（`injectable`）、`src/core/store.js`（`FM_KEYS` 加字段 + 序列化）、`index.js`（工具 schema + 写入）、`src/core/inject.js`（`rankFloating` 过滤）。

**怎么验**：
1. 一条 `有效到 = 昨天` 的记忆：`injectable` 返回 false；`recall` 仍能召回。
2. 一条没填的记忆：行为不变（向后兼容，老文件全部没有这个字段）。
3. `rankFloating` 在有 5 条过期的重要度 5 记忆时，不再被它们占满。

**风险**：`FM_KEYS` 是白名单，漏加字段会静默丢数据。改完必须写一个「存→读→字段还在」的往返测试。

---

### B3 · 上下文去重（治「同一批连着几轮重复带」）

**病**：浮上账本只记「上一轮浮过谁」（`float-log.js`），用于冷却。但同一批记忆还是可能隔一轮又整段上来。

**做法**（学 `@restregular` 的「同一版本再次命中只回 ID」的简化版）：
- `状态/浮上.json` 里给每条记 `带过: N`。
- `带过 ≥ 2` 的记忆，注入时**只给标题行，不给摘要**（现有 `DIGEST_TOP` 机制正好能复用：让它们不占摘要名额）。
- 被召回（query 模式）时仍给摘要——因为那是「真问到了」，不是闲聊轮转。

**改哪**：`src/core/float-log.js`（计数）、`src/core/inject.js`（按计数决定是否给摘要）。

**怎么验**：
1. 同一条连着三轮都被浮上：第 3 轮起没有摘要行。
2. 换个问句把它召回来：摘要恢复。
3. 账本不会无限增长（复用现有 `KEEP_ROUNDS=4` 的裁剪）。

### B4 · 召回质量测试（改之前必须先有这把尺）

**病**：24 个测试文件全绿，**没有一个**问「给定这些记忆和这个提问，召回来的是不是该出来的那条」。
测试保证了代码不崩，没保证记忆系统好用。

**做法**：建 `test/recall-quality.test.mjs`，用**真实语料**（从核里抽 20 条，脱敏后内联成 fixture），跑一批人工写好的 `{ query, 期望 id }`：

```js
const CASES = [
  { query: '上次说的修根是啥来着', expect: 'm-修根' },
  { query: '搬家的规矩', expect: 'm-搬家', note: '这条现在必然失败——字面匹配抓不住「搬家/打包」' },
  ...
]
```

**关键**：允许写「已知会失败」的用例，用 `xfail` 标记，把**真实缺陷量化**出来。
目标不是全绿，是**有一个可比较的基线**——改任何召回逻辑，跑一遍就知道变好还是变坏。

**怎么验**：造 10～20 个 case，输出 `通过 x / 失败 y / 已知缺陷 z`，失败的要打印实际召回了什么。

**风险**：fixture 从真实核抄，注意别把隐私内容带进仓库（核是私人数据）。

## 二、期 C：真正的升级

### C1 · 自我认识层（对应「咱知道自己是什么样」）

**现状实测**：画像**文件根本不存在**；可改层四段全空；观察账本 2 条。
不是长得慢，是**没有材料**——观察只记「咱表现得怎么样」，不记「这件事让咱看清了什么」。

**三层分工（必须分清，否则又是死层）**：

| 层 | 是什么 | 用途 | 进不进注入 |
| --- | --- | --- | --- |
| 观察账本 `状态/观察.jsonl` | **证据**：某天某场景发生了什么 | 过证据门 | 不进 |
| 认识 `认识/自我/*.md` | **结论**：咱大概是个什么样的 | 每轮带 | 进，≤150 字 |
| 可改层 / 画像 `人格/` | **成了的样子** | 人格段 | 进（缓存段） |

**认识条目格式**：
```yaml
---
id: r-20261109-a1b2
名: 咱被纠正后先去查证，不辩解
陈述: 指出咱说错了时，第一反应是承认，然后去翻原始记录，而不是解释自己为什么那么想。
依据: o-20261108-夜间, m-20261108-9c11
置信: 0.7
上次确认: 2026-11-09
状态: active        # active / 弱化 / 被取代
---
```

**三条铁律**：
1. **每条必须带 `依据`**（指向观察或记忆的 id）。没有依据的认识是自我美化，不收。
2. **不按时间衰减，按推翻降置信**。一件事会过时，但「咱是什么样」不会因为三个月没提就失效。
3. **写的是「咱」，不是「她」**。自评空话不算，要写具体行为倾向。

**怎么产生**：先靠蓝曦自己写（零成本，当事人视角）；量起来之后再加「定期扫一遍观察账本，看有没有漏升的」（要模型调用）。

**改哪**：`src/store.js layout()` 加 `认识` 目录、新文件 `src/core/self-knowledge.js`、`index.js`（工具 + 注入）、`inject.js`（新块，走 `context` 不走 `section`）。

**怎么验**：
1. 写一条认识 → 注入里出现，且 ≤150 字。
2. 没有认识时不留空块。
3. 一条认识同时有 `依据` 里的两个 id 存在 → 能反查。
4. **关键**：把它放进缓存段会掉缓存，测试要断言它在 `context` 不在 `section`。

### C2 · 共同经历（对应「咱知道我们一起做过什么」）

**病**：59 条长期事件是平铺的，没有「我们一起做过这几件大事」。

**做法**：**机械生成**，不调模型。
- 每月一份 `认识/经历/<YYYY-MM>.md`：把该月所有「事件」类记忆按日期排成一行一条。
- 格式极简：`- 11.08 核做成了：能跑能搬能备份`
- **不进注入**（主人 11-09 定：回顾性的东西平时不需要每轮带着）。只做「问得出来」。

**怎么验**：`benwo_self` 或新工具能按月取；文件里条数与当月事件数一致。

---

### C3 · 人格门槛放宽（**依赖 C1**）

**病**：门是 2 天 × 2 场景 × 3 证据 × 均值 ≥0.7 × 下界 >0.45 × 近 14 天无反向。
过了门一次只改 1 句、幅度 ≤20%、只有 4 段。**正常聊一周才动一句话。**

**为什么必须等 C1 再动**：现在放宽也写不出东西——没有「认识」这一层供料，放宽了只能写「咱更温柔了」这种空话。**先有材料，再开门。**

**做法**（C1 落地并跑够两周后再评估）：
- 候选一：`MIN_SCENES` 2→1（场景是最难凑的一项）
- 候选二：允许一次改 2 句
- 候选三：把「画像」的门与「可改层」的门分开（画像更长、更慢，可改层更短、可快）

**怎么验**：放宽前后各统计「30 天内人格实际改了几次」——现在预期是 0～1 次，目标 2～4 次。

## 三、工程卫生（⑧⑨⑩⑪）—— 本夜处理状态

| 编号 | 问题 | 状态 |
| --- | --- | --- |
| ⑩ | schema 有版本号，没有迁移逻辑 | **已补**（`migrateCore`，开机由 `ensureCore` 调） |
| ⑪ | `withLock` 是进程内的，DSH 和 QQ 桥同时写会打架 | **已补**（`withDiskLock`，`appendToday` 已接） |
| ⑧ | 「今天」只增不减，没有月末归档 | 待办（低成本，下一个会话可做） |
| ⑨ | 隐私模式是工作区布尔值，粒度太粗 | 待办（要动写入 + 注入两处，成本中等） |

回归锁：`test/hygiene.test.mjs`（9 项）。全套 **24 个文件 / 313 条断言全绿**（2026-11-09 深夜复核；进度账见 `体检与待办总账.md`）。

### ⑩ 的补法
`store.js` 里加 `migrateCore(L)`：
- 读 `状态/state.json` 的 `schema`。
- 等于当前 `SCHEMA` → 什么都不做。
- **小于** → 按版本逐级升级（目前只有 1，所以是空实现 + 留钩子）。
- **大于**（旧代码打开新核）→ **拒绝启动**，不猜、不静默降级。
- 迁移前先写一份 `.bak`。

### ⑪ 的补法
- 锁外再加一层**独占文件**：`<核>/.lock`，用 `fs.open(path, 'wx')` 创建（已存在 = 别人在写，等一会儿再试）。
- 超时（比如 5 秒）就放弃并报「有别的进程正在写这个核」，**不静默继续**。
- 进程退出时删锁；异常退出留下的陈旧锁，靠「文件里写 pid + 时间戳，超过 10 分钟算陈旧」清理。

## 四、不要做的事（有人会顺手加回来的）

- **向量库 / embedding**：违背「核是能拷走的文件夹」。`@jipika`、`dsh-memory-tiers` 纯文件也能跑。
- **自动判重阈值**：实测过，真重复 0.196 / 不相干 0.659，字面相似度判不了（见 `升级计划-v1.md` §7.1）。
- **用记忆替代对话历史**（`dsh-memory-tiers` 的「替」）：会丢语气和节奏，而语气本身就是人格。
- **注入里塞工坊目录**：主人 11-09 定，工坊会日积月累，目录进上下文会越来越占。改成「问起来就去查」。
